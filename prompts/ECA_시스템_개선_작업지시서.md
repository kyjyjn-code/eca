## 3. 진단 요약 — 왜 이 작업인가

8월 회차 점검에서 확인된 신규 발굴 0건, coverage.md 미생성, 확인수준 표기 0건, 포스터 0건은 별개의 문제가 아니라 하나의 구조적 원인의 네 증상이었다: **지시문에만 있고 기계가 검증하지 않는 일은 조용히 생략된다.** 마스터에서 기계적으로 열거되는 재확인(마감 임박·제외 복구)은 완벽히 수행됐고, 열거 목록이 없는 개방형 과제(신규 발굴)만 통째로 증발했다.

## P0-1. `scripts/make-targets.js` 신설 (파이프라인 0.5단계)

**목적** — 리서처가 처리해야 할 대상을 결정적 스크립트가 열거해 `data/raw/YYYY-MM.targets.json`으로 만든다. 날짜 연산과 대상 산정을 LLM에서 완전히 제거한다.

**입력** — `data/sources.json`, `data/master.json`, `data/inbox.json`(있으면), 배제 목록.

**출력 구조** (섹션 7 + 목표):

```json
{
  "회차": "2026-09",
  "A_미수록_씨앗": [
    { "canonical_slug": "kmo", "이름": "한국수학올림피아드", "유형": "회차형", "예상_공고월": [3, 9], "이번달_공고예상": true }
  ],
  "B_시즌캘린더_당월": [],
  "C_순회소스": [],
  "D_쿼리세트": { "국문": [], "영문": [] },
  "E_재확인_마감임박": [],
  "F_재확인_제외복구": [],
  "G_교사제보": [],
  "목표": {
    "신규_선발형_최소": 3,
    "주의": "목표 미달은 실패가 아니다. 검증 필터 완화 금지. 미달 시 coverage에 사유 기록으로 갈음"
  }
}
```

**미수록 판정 규칙 (중요)** — id 완전일치가 아니라 **canonical_slug 접두 매칭**. 회차형 씨앗은 "현재 시즌에 해당하는 개최연도 id"가 마스터에 있는지로 판정한다(예: 2026-09 시점의 amc는 `amc-2026` 존재 여부, 2027-01 시점에는 `amc-2027` 존재 여부). 상시형 씨앗은 slug 일치로 판정한다.

**분기 모드** — 1·4·7·10월에는 E 섹션에 마스터 전 항목을 포함하고(분기 전량 재검증 대상 산정도 스크립트가 담당), D_쿼리세트에 `소스탐색` 소그룹(§P1-6)을 추가한다.

**우선순위 배치** — `data/retro/kpi.json`의 최신 커버리지 매트릭스(§P0-5)를 읽어, 빈 칸이 많은 대분류의 씨앗·쿼리를 targets 상단에 배치한다. 매트릭스가 아직 없으면(첫 실행) 이 규칙은 생략한다.

**동반 데이터 보강 (`data/sources.json`)** — 씨앗 46개 각각에 `canonical_slug`, `유형("회차형"|"상시형")`, `예상_공고월`(월 숫자 배열) 필드를 추가한다. 예상_공고월은 공개 정보 기반 초안으로 채우되, 불확실하면 `null` + `"확인필요": true`로 둔다. 아울러 분기용 `소스탐색` 쿼리 3~5개(§P1-6)를 함께 정의한다. 초안 전체를 pr-body에 표로 실어 사람 검토를 받는다.

**수용 기준** — 2026-08 마스터 기준 실행 시 ① KMO·John Locke·RSI 등 미수록 씨앗이 A에 뜬다 ② `amc-2026`이 있으므로 amc는 A에 뜨지 않는다 ③ 회차를 2027-01로 강제하면 amc가 A에 뜬다. 세 케이스를 테스트로 작성한다.

## P0-2. `scripts/check-coverage.js` 신설 (파이프라인 1.5단계)

**목적** — 리서치 산출 직후 기록 누락을 잡아 조기에 파이프라인을 멈춘다. 게시 직전(9단계)이 아니라 리서치 직후(1.5단계)에 두는 이유는 실패 비용을 최소화하기 위해서다.

**실패 조건 (exit 1)**
1. `data/raw/YYYY-MM.coverage.md` 부재
2. targets 전 항목에 대한 처리 결과 누락 (필수 섹션 ① 기준)
3. 신규 수록 0건인데 "신규 0건 사유" 섹션 부재
4. `data/raw/YYYY-MM.json`의 항목 중 근거_원문에 `[확인수준: …]` 표기가 없는 것이 하나라도 존재
5. 필수 섹션 ⑦(소스 관찰 로그) 부재 — "특이사항 없음" 한 줄 기재도 충족으로 인정

**coverage.md 필수 섹션** — 템플릿을 `templates/coverage-template.md`로 저장하고 researcher.md에서 참조하게 한다.
- ① 타깃 처리 결과 표: targets의 모든 항목 × 처리 결과(수록 / 배제-사유·탈락 필터명 / 시즌아님-예상 공고월 / 확인불가-사유)
- ② 쿼리 실행 로그: 쿼리별 실행 여부, 후보 수확 수, 후보가 발견된 출처 도메인
- ③ 순회 소스 방문 로그: 5곳 각각 방문 여부와 발견 수
- ④ 배제 후보 기록: 발굴됐으나 3층 필터에서 탈락한 후보 + 탈락 필터명 + 근거 한 줄 + 출처 도메인
- ⑤ 시즌 점검: 캘린더 대비 누락 여부
- ⑥ 신규 0건 사유 (해당 시에만)
- ⑦ 소스 관찰 로그: 신규 소스 후보(도메인·발견 활동·공신력 단서)와 기존 소스의 이상 징후(상업성 오염, 주최 불명 활동 비중 증가, 운영 주체·사이트 성격 변화). 특이사항이 없으면 "특이사항 없음"으로 기재한다 — 빈칸과 미작성을 구분하기 위해서다.

**수용 기준** — 실패 5종을 각각 인위 재현해 exit 1을 확인한다(§V-2).

## P0-3. 확인수준 표기를 무조건 표기로 전환

- researcher.md: 모든 항목의 근거_원문 끝에 `[확인수준: 요강원문]` / `[확인수준: 공고요약]` / `[확인수준: 연도불명]` 중 하나를 **반드시** 붙인다. 최고 신뢰 등급이어도 생략하지 않는다.
- 이유: 현행 규칙(최고 신뢰 시 생략)에서는 표기 0건이 "전부 원문 확인"인지 "규칙 미이행"인지 구분되지 않는다. 무조건 표기로 바꾸면 표기 부재 = 규칙 위반이 되어 P0-2의 조건 4가 기계 검증한다.
- 기존 마스터 16건의 소급 표기는 이번에 하지 않는다. 10월 전량 재검증에서 채우며, 대상 목록은 §P2-4의 pending 파일에 등재한다.

# P1. 발굴 복원

## P1-1. `.claude/agents/researcher.md` 재구성

핵심은 **발굴과 재확인의 분리**, 그리고 **종료 조건**이다. 아래 문안을 기존 내용과 통합해 반영한다(기존의 환각 방지·기록 규칙은 유지하되, 아래와 충돌하는 문구는 아래가 우선한다):

```markdown
## A. 신규 발굴 — 매월 무조건 수행한다
증분 수집 원칙은 아래 B(재확인)에만 적용된다. 신규 발굴은 매월 예외 없이 수행한다.
targets.json의 A(미수록 씨앗)·B(시즌)·C(순회 소스)·D(쿼리)·G(교사 제보) 전 항목을 처리하고,
각 항목의 처리 결과를 coverage.md에 기록하기 전에는 작업을 종료할 수 없다.

- 목표: 신규 선발형 3건. 단, 목표를 채우기 위해 3층 검증 필터를 완화하는 것을 금지한다.
  근거 없는 1건은 0건보다 나쁘다. 미달 시 coverage.md에 사유를 기록하는 것으로 갈음한다.
- 신규 후보가 0건이면 그 자체를 이상 신호로 간주하고, 쿼리·소스별로 무엇을 확인했고
  왜 후보가 없었는지를 coverage.md ⑥에 기술한다.
- 발굴됐으나 필터에서 탈락한 후보도 coverage.md ④에 탈락 필터명·사유와 함께 남긴다.
  (같은 후보를 다음 달에 다시 평가하지 않기 위한 기록이다.)

## B. 재확인 — targets가 지정한 것만
E(마감 임박)·F(제외 복구) 목록의 항목만 재확인한다. 목록 밖의 정상 게시 항목은 재조사하지 않는다.
분기월(1·4·7·10월)에는 E에 전 항목이 포함되므로 그대로 따른다.

## C. 기록 규칙 (추가·강화)
- 모든 항목의 근거_원문 끝에 [확인수준: 요강원문|공고요약|연도불명] 중 하나를 반드시 붙인다.
  생략은 규칙 위반으로 기계 검증된다.
- 수록하는 각 활동마다 공식 페이지에서 포스터·배너 이미지 URL을 1회 탐색한다.
  없으면 포스터_url을 비우고 coverage.md 타깃 표에 "포스터 없음"을 기록한다.
- coverage.md는 templates/coverage-template.md의 필수 섹션 ①~⑦ 구조를 따른다.

## D. 소스 관찰 — 기록만 하고, 추가·제거하지 않는다
- 조사 중 자격 충족 활동이 반복적으로 발견되는 허브·사이트를 만나면 sources.json에
  추가하지 말고 coverage.md ⑦에 기록한다: 도메인, 발견한 활동, 공신력 단서(운영 주체 등).
- 순회 소스 방문 중 이상 징후(상업성 공고 급증, 주최 불명 활동 비중 증가, 운영 주체 변경,
  사이트 성격 변화)를 발견하면 같은 곳에 기록한다.
- 분기월에는 targets의 `소스탐색` 쿼리를 실행하되, 결과는 활동 수집이 아니라 ⑦ 기록으로만 남긴다.
- 소스의 추가·제거·강등은 회고의 제안과 사람 승인을 거친다. 리서치 중 실시간 변경은 금지한다.
```

# P2. 별점 개편 — A안, 즉시 재산정 (D2 · D3)

## P2-1. 계산식 교체 (CLAUDE.md)

## P3-1. 연간 캘린더 뷰 — "공고 예정" 표시

**목적** — 지금 열린 활동만 보이는 사이트를 연간 지도로 확장한다. 9월의 학생이 겨울에 오는 여름 프로그램 마감을 미리 보고 준비할 수 있게 하는 것이 핵심이며, 현재 게시 건수의 체감 빈약함도 함께 완화된다.

**데이터원 두 가지**
1. master의 게시 활동 — 마감일 기준으로 해당 월에 배치한다.
2. sources.json의 씨앗 중 미수록이면서 예상_공고월이 있는 항목 — "공고 예정" 카드로 해당 월에 배치한다.

**예정 카드 규칙 (엄격)**
- 라벨 필수: **"공고 예정 · 예상 N월 (전년도 기준, 확정 전)"**.
- 표시 정보는 활동명·분야·예상 시기·공식 사이트 링크까지만. 마감일·자격·비용 등 근거_원문이 확보되지 않은 상세 정보는 표시하지 않는다.

**뷰** — 월별(1~12월) 타임라인. 각 월에 "이달 마감"(게시 활동)과 "공고 예상"(씨앗 예정)을 구분해 표시한다. 모바일 우선으로 구현한다.

**가드레일 추가** — `check-guardrails.js`에 검사를 추가한다(검사 추가는 허용 원칙에 부합): 공개 산출물에 "공고 예정" 표시가 존재하면 "전년도 기준"과 "확정 전" 고지가 함께 존재해야 통과.

```markdown
1. KPI 진단표 — 지표별 당월값, 전월 대비, 임계 위반 여부. 커버리지 매트릭스의 빈 칸과 변화를 포함한다.
2. 원인 가설 — 위반·이상 지표마다 coverage·리포트의 구체 기록을 인용해 가설을 세운다.
   기록에 근거가 없는 추정은 "추측"이라고 명시한다.
3. 전월 추적 — 전월 제안의 반영 여부(changelog 대조)와, 반영된 변경의 기대 효과 대비
   실제 KPI 변화. 효과가 없거나 악화면 롤백을 제안한다. changelog 기재 누락이 보이면 지적한다.
4. 신규 제안 — 최대 3건. 각 제안은 아래 양식을 따른다.
   당월 coverage ⑦에 소스 신뢰 이상 징후가 기록돼 있으면 분기를 기다리지 않고 여기서 우선 다룬다.
5. 다음 달 관찰 포인트 — 이번 달 반영분의 효과를 확인할 지표.
```

## R-3. `data/retro/changelog.md` 신설 + 운영 규칙

